# M7 — Polish and ship

**Goal:** a public, self-explanatory Genus Loci on Vercel that judges can open and understand in under a minute, plus the repo and Devpost materials.

**Decisions (user, 2026-10-14):**
- Deploy to Vercel under the user's account, with the Qloo and DeepSeek keys as encrypted environment variables and GitHub auto-deploys.
- World files live in a **private Vercel Blob** store, never in git (Qloo terms).
- **Prebuilt cities only:** add New York for the US judges. No open-ended on-demand builds, to protect the Qloo quota.

## Status (2026-10-14)

Tasks 1–7 are done; the site is live at https://genusloci-culture-simulator.vercel.app.

- **Framework preset:** the first deploy served 404s, because creating the project with `vercel project add` left the preset as "Other". `vercel.json` now pins `"framework": "nextjs"`.
- **Env file:** `vercel blob create-store` rewrote `.env.local` from the development environment and dropped the local Qloo key. See the caution in architecture.md.

## Tasks

1. **World storage.** `/api/world/[slug]` reads `.cache/worlds` locally, otherwise the private Blob store (`BLOB_READ_WRITE_TOKEN`, server-side only). `pnpm upload:worlds` uploads the built worlds.
2. **New York.** `pnpm build:geo newyork` (one Overpass request), then `pnpm build:world newyork`. Calibrate and add it to the city switcher.
3. **Serverless settings.** Set `QLOO_CACHE_DIR=/tmp/qloo` for the co-pilot's Qloo cache. Check the routes' `maxDuration` values.
4. **Vercel.**
   - Create and link the project; set `QLOO_API_KEY`, `DEEPSEEK_API_KEY` and the Blob token.
   - Deploy to production.
   - Smoke-test the cities, co-pilot, names and interviews on the live URL.
5. **Onboarding.** A short first-visit intro covering what this is, what the dots and lights mean, and three things to try (play, ask the co-pilot, talk to a resident). It can be dismissed and is remembered per browser.
6. **README.** The pitch, a screenshot, the live link, how it uses Qloo, the architecture, how to run it, data and licence notes (no Qloo data in the repo; OSM ODbL).
7. **Devpost write-up draft** (`docs/devpost.md`): inspiration, what it does, how it's built, Qloo usage, challenges, what's next.
8. **Docs:** architecture, current state, roadmap.
