# Plan 5c: Promoter Tools — Scout a Location — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer a promoter's real question, "Where should I host a night for this headliner?", with evidence from the taste graph.
1. Pick a headliner.
2. See a demand glow where residents' taste fits them.
3. The tool proposes 3 well-spaced candidate spots, and you can add a 4th of your own.
4. It simulates the event at each spot in forked futures, alongside a no-event baseline.
5. A compare panel ranks the spots on turnout, new fans, scenes reached and harm to nearby venues.
6. "Book it" schedules the event in the live city.

**Architecture:**
- **Pure sim functions** (`src/sim/scout.ts`): `demandByCell` (per-cell sum of residents' `affinityToEntity` to the headliner), `pickCandidates` (top-demand cells at least a minimum distance apart), and `scoutCandidates` (fork the state per candidate plus a baseline, run N weeks, measure).
- **Worker commands:** `demand` and `scout`.
- **UI:** a new Scout tool mode with a demand glow, A–D candidate pins, and a compare panel.

The verdict is template text; the Plan 6 co-pilot will narrate it later. **Book for my venue** follows in a later plan on the same engine.

`src/sim/scout.ts`:
```ts
import { affinityToEntity, geneSlot } from "@/sim/genome";
import { cloneState, type SimState } from "@/sim/state";
import { step } from "@/sim/step";
import { distKm } from "@/sim/world-index";

export type ScoutOptions = {
  entity: number;
  /** Weeks to simulate per candidate. */
  weeks: number;
  duration: number;
  reachKm: number;
  capacity: number;
  /** Venues within this distance of a candidate count towards neighbourLoss. */
  nearbyKm: number;
};

export type ScoutResult = {
  cell: number;
  /** Total visits to the event across the simulated weeks. */
  turnout: number;
  /** Residents who didn't have the headliner in their taste before and do after. */
  newFans: number;
  /** Lineage ids of the scenes that came, most attendees first. */
  scenes: number[];
  /** Visits lost by nearby permanent venues compared with the no-event baseline. */
  neighbourLoss: number;
  score: number;
};

/** Per cell: summed taste-graph affinity of its residents to `entity` (who'd want to come). */
export function demandByCell(s: SimState, entity: number): number[] {
  const out = new Array<number>(s.cw.nCells).fill(0);
  for (let i = 0; i < s.alive.length; i++) {
    if (s.alive[i]) out[s.homeCell[i]] += affinityToEntity(s.genomes, i, s.cw, entity);
  }
  return out;
}

/** The `count` highest-demand cells, each at least `minKm` from those already picked. */
export function pickCandidates(s: SimState, demand: number[], count: number, minKm: number): number[] {
  const order = demand.map((d, c) => [d, c] as const).sort((a, b) => b[0] - a[0] || a[1] - b[1]);
  const picks: number[] = [];
  for (const [, c] of order) {
    if (picks.length >= count) break;
    if (picks.every((p) => distKm(s.cw, p, c) >= minKm)) picks.push(c);
  }
  return picks;
}

const fansOf = (s: SimState, entity: number) => {
  const fans = new Uint8Array(s.alive.length);
  for (let i = 0; i < s.alive.length; i++) if (s.alive[i] && geneSlot(s.genomes, i, entity) >= 0) fans[i] = 1;
  return fans;
};

/**
 * Simulates the event at each candidate cell in a forked future, alongside a no-event baseline
 * fork, and ranks the candidates. The live state is never modified.
 */
export function scoutCandidates(live: SimState, cells: number[], o: ScoutOptions): ScoutResult[] {
  const before = fansOf(live, o.entity);
  const baseline = cloneState(live);
  const baseVisits = new Float64Array(baseline.venueEntity.length);
  for (let w = 0; w < o.weeks; w++) {
    step(baseline);
    for (let v = 0; v < baseline.nVenues; v++) baseVisits[v] += baseline.venueAttendance[v];
  }

  const results = cells.map((cell): ScoutResult => {
    const s = cloneState(live);
    const [res] = step(s, [{ type: "scheduleEvent", entity: o.entity, cell, duration: o.duration, reachKm: o.reachKm, capacity: o.capacity }]);
    const slot = res.ok && res.venue !== undefined ? res.venue : -1;
    let turnout = 0;
    const sceneCounts = new Map<number, number>();
    const visits = new Float64Array(s.venueEntity.length);
    const tally = () => {
      for (let v = 0; v < s.nVenues; v++) visits[v] += s.venueAttendance[v];
      if (slot < 0) return;
      turnout += s.venueAttendance[slot];
      for (let i = 0; i < s.attendance.length; i++) {
        if (s.attendance[i] !== slot) continue;
        const a = s.scenes.assignment[i];
        if (a >= 0) {
          const id = s.scenes.live[a];
          sceneCounts.set(id, (sceneCounts.get(id) ?? 0) + 1);
        }
      }
    };
    tally();
    for (let w = 1; w < o.weeks; w++) {
      step(s);
      tally();
    }
    const after = fansOf(s, o.entity);
    let newFans = 0;
    for (let i = 0; i < after.length; i++) if (after[i] && !before[i]) newFans++;
    let neighbourLoss = 0;
    for (let v = 0; v < Math.min(s.nVenues, baseline.nVenues); v++) {
      if (v === slot || s.venueExpires[v] >= 0) continue;
      if (distKm(s.cw, cell, s.venueCell[v]) > o.nearbyKm) continue;
      neighbourLoss += Math.max(0, baseVisits[v] - visits[v]);
    }
    const scenes = [...sceneCounts.entries()].sort((a, b) => b[1] - a[1] || a[0] - b[0]).map(([id]) => id);
    return { cell, turnout, newFans, scenes, neighbourLoss, score: turnout + 3 * newFans - 0.5 * neighbourLoss };
  });
  return results.sort((a, b) => b.score - a.score || a.cell - b.cell);
}
```

**Files:** modify `src/sim/worker/protocol.ts`, `src/sim/worker/host.ts`, `src/sim/worker/client.ts`; extend `src/sim/worker/host.test.ts`.

- **Protocol:** add these commands:
  - `{ type: "demand"; timeline: string; entity: number }`, result `{ demand: number[]; candidates: number[] }`. The candidates come from `pickCandidates(state, demand, 3, minKm)`, where `minKm` is about 0.5 km, or larger if cells are sparse: use `max(0.5, 1.2 × median nearest-cell distance)`.
  - `{ type: "scout"; timeline: string; entity: number; cells: number[]; weeks?: number }`, result `{ results: ScoutResult[]; baselineTick: number }`.

  Defaults: weeks 4, duration 3, reachKm 25, capacity 3000, nearbyKm 1.
- **Validation:** check the entity and cells against the world, cap `cells` at 4, and cap weeks at 1–12. Invalid input returns `ok: false`.
- **Client methods:** `demand(timeline, entity)` and `scout(timeline, entity, cells, weeks?)`.
- **Tests in `host.test.ts`:**
  - `demand` returns one value per cell and up to 3 candidates;
  - `scout` returns ranked results and leaves the timeline's tick unchanged;
  - an invalid entity or cell gives `ok: false`.

- **On entering scout mode:**
  - pause playback, so the comparison is about this moment in the city;
  - call `demand`;
  - show the **DemandGlow**: per-cell soft amber discs, reusing the hotspot/aura shader approach, with intensity normalised to the max demand and a subtle look with no white wash;

  - then call `scout` automatically on those candidates.
- **Your own pin:** clicking the map in scout mode adds pin D at the nearest cell (max 4; clicking again moves D) and re-runs `scout`.
- **`ScoutPanel`** (right column; it replaces the scene legend while scouting):
  - a title, "Where should {headliner} play?";
  - a loading state while scouting, "Simulating 4 weeks at each spot…";
  - one card per candidate, ranked, showing:
    - the letter and area name (from `words.ts`, e.g. "the north-east");
    - turnout, new fans and nearby venues hurt (number plus a small bar relative to the best);
    - the scenes reached, as coloured dots with "Scene N" labels;
  - a one-line verdict from `scout-words.ts`, e.g. "B is the strongest night: 38% more turnout than A, reaches 3 scenes, and costs nearby venues little." Unit-test the verdict wording for: a clear winner, a close call, and a winner that hurts neighbours a lot.
  - **Hovering a card** highlights its pin and flies the camera there gently.
  - **"Book it"** on a card schedules the event at that cell in the live timeline (the existing `scheduleEvent` act), exits scout mode, shows a toast ("Booked {headliner} in {area}"), and resumes play if it was playing before.
  - **"Cancel"** or **Esc** exits scout mode with nothing booked.
- **Rendering:** the demand glow and pins render only in scout mode, and the scene auras dim while scouting.
- **Accessibility:**
  - the panel has `aria-label="Scout results"`;
  - cards are buttons or list items with clear labels;
  - "Book it" is a real button;
  - focus moves to the panel when results arrive.
